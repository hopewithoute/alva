# Alva SDK DX Overhaul

## Objective
Overhaul the frontend SDK generated by Alva to provide a highly coherent, world-class Developer Experience. The new SDK will unify all surface areas (Actions, Signals, Forms, Queries, Uploads) under a single entry point (`useAlva()`) with a strict domain-nested structure, while keeping 1:1 `snake_case` mapping with the backend.

## Design Decisions
1. **Single Entry Point**: Replace `useAlvaApi()` and `ash.on()` with a unified `const alva = useAlva()`.
2. **Domain-Nested**: Methods are accessed via their Ash domain (e.g., `alva.sales.create_order`).
3. **Promise Fix**: Action commands properly return `Promise<AlvaResult<T>>` in TypeScript, fixing `await` behavior in the IDE.
4. **Signals**: Accessible via `alva.<domain>.on_<signal>(cb)`.
5. **Forms**: Dedicated composable per action: `alva.<domain>.use_<action>_form(options)`.
6. **Query Builder**: Reactive read wrapper per action: `alva.<domain>.use_<action>_query(payload_getter, options)`.
7. **Uploads**: Mounted at root `alva.use_upload(name)` since it depends on LiveVue configs, not Ash domains.
8. **TypeScript Accuracy**: Inject `page` and `sort` into the `InputContract` for read actions to leverage existing Ash capabilities.
