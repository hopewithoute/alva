# Collections Are Server-Owned Reactive Lists

Alva will expose realtime list state through a `collection` DSL, not a public `stream` DSL. A Collection is unified at the developer-facing API level, but internally it is a thin declarative mapper onto Phoenix LiveView streams and LiveVue stream diffs, not a separate list reconciliation engine; plain props remain assigns, Signals remain push events, and Commands keep their immediate replies. Every Collection must declare an explicit `source` for initial/reset data instead of relying on read-action inference, because a Collection is defined as source snapshot plus optional Event-triggered deltas. The source records are inferred from the source event's Auto-DTO/projection contract, not from extra shape options on the Collection. Ambiguous custom DTO envelopes fail clearly during Collection activation with a message naming the collection and source event. Alva should lean on native LiveView semantics for identity (`dom_id`, defaulting to `id`), duplicate handling (`stream_insert`/LiveVue upsert), missing-update behavior (`update_only: true`), insertion position (`at:`), reset, delete, and limit rather than inventing new semantics. Insert/update/delete operations are optional, with source-only Collections producing a warning because they will not update from PubSub. Declarative `collections: [...]` is the default page activation path for Route Collections, `route_subscriptions:` is the per-projection topic wiring path when deterministic inference is not available, and ambiguous inference should fail loudly rather than subscribe too broadly. The resource-level `collection` block declares reusable capability, while route activation owns current Source Input, optional `reload_on: :route_change`, and any route-local refresh behavior. Manual helpers remain as the escape hatch for conditional activation, graceful not-found handling, route-state changes, custom subscription lifecycles, and complex multi-step setup. Collection activation supports Source Input, defaulting to `%{}`. Render still passes `@streams.collection_name` to Vue explicitly as the UI contract. This preserves the Phase 9 server-owned collection model and allows temporary `v-diff={false}` and plain assign route-collection workarounds in the sample app to be removed once Collections are implemented properly.
